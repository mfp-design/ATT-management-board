## 撮影で確認した再設計上の注意

1. **スマホのナビゲーション**：メニュー文字が縦に折り返され、横スクロールも必要になる。再構築では項目を選びやすいメニューを設計する。撮影操作中にも遷移先を確認して撮り直した。自動操作だけの事象をアプリの確定不具合とは断定しない。
2. **スマホの表とカンバン**：右側の列・編集ボタンが初期表示に収まらない。主要情報と操作を優先し、一覧・詳細を再構成する。PCでも長い受注列は縦、6段階全体は横スクロールになる。
3. **長い入力フォーム**：内部スクロールで下のメモ等へ移動する。入力順・検証エラー・キーボード操作は新設計で確認する。ここでは保存や入力検証の動作テストをしていない。
4. **スマホのダッシュボード**：カードが2列となり、グラフと期限タスクは下方へ続く。新要件の閲覧・フィルター・支援コメントを優先して配置する。
5. **業務仕様の境界**：旧画面にない経費、入金、月次締め、監査、権限等は、この資料に合わせて省略しない。旧ナビにある顧客機能の存在だけでPhaseを前倒ししない。

## 検証と再現

主要8画面と8フォームをPC・スマホで照合。空状態、全タスク、取引先編集、削除確認、長いフォーム下部も保存。画像は目視で確認し、撮影台帳とのファイル対応・画像寸法・ハッシュを検証した。ダーク表示の視覚記録であり、全テーマ・全端末の品質保証ではない。

撮影用データからページを再生成する手順（リポジトリ直下で実行）：

```sh
node docs/visual-reference/build-preview.cjs /private/tmp/att-visual-preview
python3 -m http.server 4174 --bind 127.0.0.1 --directory /private/tmp/att-visual-preview
```

ブラウザーで `http://127.0.0.1:4174/` を開く。既に4174番で起動している場合は再起動不要。新コードへ旧ランタイムを取り込むためのスクリプトではなく、視覚参照の再現にだけ使用する。
