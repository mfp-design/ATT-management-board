## 再現した不具合

### W01: 同名の別取引先を統合すると、無関係な既存案件まで付け替わる

重要度: 高（画面案のデータ関係）。P11 は不合格。

1. 再読み込みし、総務担当→取引先を開く。
2. 既存の「サンプル商事 / A-001」がある状態で、同名の「サンプル商事 / 法人」を別取引先として登録する。
3. 新規IDの行だけから「統合を確認」を開く。今回の新規IDは `A-1789472176224`。
4. 統合先に `A-002 / サンプル企画`、理由に「QA：新規の同名法人だけを企画へ統合」を指定し、確認・確定する。
5. 取引先一覧に元の `A-001 / サンプル商事` が残っていることを確認して案件へ移動する。

期待: 2つの同名取引先のうち、統合した新規IDの参照だけが変わる。新規IDには案件を作っていないため、既存案件への変更は0件。

実際: 「ライフプラン継続支援」「保険相談 継続サポート」の取引先が、どちらもサンプル商事からサンプル企画へ変わる。統合履歴には新規IDだけを統合したと表示される。

原因: `src/workflow-panels.jsx:31` は `accountId` 未設定の案件を名称一致でも統合対象にする。`src/data.js:4` からの初期案件は `accountId` がなく、別IDとして新規登録した同名取引先の統合に巻き込まれる。初期データにも識別子を与え、統合はIDだけで関連を更新する必要がある。

要件根拠: 要件定義書 7.2「取引先の最小情報」、同名を許容し自動で同一法人と確定しないこと、8.1 の履歴保持。これは実DB未接続という許容された簡略化とは別の、画面上の誤った関連変更。

証拠: [統合元と統合先の確認](workflow-merge-confirm.png)、[無関係な既存案件の変更結果](workflow-merge-unrelated-deals.png)。

### W02: 事業無効化で開始日より前の終了日を保存できる

重要度: 中。P13 は不合格。

1. システム担当→事業・メンバーで、日本酒（開始日 `2025-10-01`）の「無効化」を押す。
2. 終了日を `2025-09-30`、理由を「QA：期間逆転の検証」にする。
3. 「内容を確認」→「確定する」。

期待: 終了日が開始日より前であるエラーを表示し、保存しない。

実際: `2025-10-01 — 2025-09-30 / 無効` と保存される。無効化した日本酒が新規案件の選択肢から外れる点は正常。

原因: `src/admin-panels.jsx:28` の無効化フォームには期間検証がない。通常の登録/編集には同ファイル26行に期間逆転を拒否する検証があり、無効化だけ不整合。

証拠: [逆転した有効期間](workflow-organization.png)。

### W03: 所属ごとの期間を設定できず、兼務変更の前後値も履歴で確認できない

重要度: 中。P13 の所属期間・変更履歴は不合格。

1. システム担当→事業・メンバー→担当Bを編集する。
2. 主所属 MoneRun はそのまま、兼務先に FP事業と企業研修を選択し、理由「QA：兼務を追加」で保存する。
3. 所属・履歴の表示を確認する。

期待: 兼務が「なし→FP事業・企業研修」と変わったことを確認できる。また MoneRun、FP事業、企業研修それぞれの所属開始日・終了日を設定できる。

実際: 現在の兼務先は正しく表示されるが、履歴は `担当B / MoneRun → 担当B / MoneRun` のみ。フォームの開始日・終了日はメンバーに1組だけで、各所属の有効期間を指定する欄がない。

原因: `src/admin-panels.jsx:24`〜27 はメンバー自身に1組の start/end と primary/additional を保存し、履歴の before/after は名前と主所属だけを文字列にする。旧兼務・所属期間の前後値は含まれない。要件定義書 8.1（563行）「各所属に開始日と終了日を持たせる」を画面として表現できていない。過去時点の実DB復元は後続としても、その入力・履歴を確認する画面項目は不足している。

証拠: [兼務追加後の表示・履歴](workflow-organization.png)。

## 許容した簡略化と未検証範囲

- すべてブラウザー内の架空状態であり、再読み込みで戻ることは案内どおり。Googleログイン、永続化、Slack通知、課金、実バックアップ・復元、同時編集サーバー処理の成功とは扱っていない。
- 「運用開始前」を再選択すると状態を戻せることは、上部の画面確認用コントロールであり、運用開始の不可逆性違反とは扱わない。
- 日付サンプルの基準が9/11、現在時刻の記録が9/15となることは既知のサンプル仕様。
- 復元・年度変更の実施ボタンがないのは README 明記の「承認後の適用待ちまで」という範囲。承認者・承認日時の監査の本実装は別途必要。
- 登録済み取引先の名称・種別を通常編集する入口は表示されず、AccountsPanelにも編集処理がない。P11の今回の限定チェック（同名候補・統合）とは別に、要件定義書744行の取引先修正を対象に画面一覧の過不足レビューへ残す。
- 画面案の日本デザイン未反映は既知事項として重複指摘を避けた。
- スクリーンショットは既定 viewport の保存。IAB の fullPage 画像は下端の重複が見られたため、証拠には viewport 画像だけを採用した。実機端末・OS差・視覚的な業務適合性・役員の最終確認は今回の担当範囲外。
