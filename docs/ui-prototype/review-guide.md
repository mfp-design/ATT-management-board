# 一次レビューの操作手順

対象: [Phase 1画面案](README.md) / 2026年9月15日

[プレビューを開きます](http://127.0.0.1:4176/)。すべて架空データです。各項目の最初に再読み込みすると初期状態へ戻せます。通常は上部の状態を「通常」にしてください。

## 1. 指標・期間・役割

1. 経営者の9月ダッシュボードで、売上計上額700,000円、着地見込み1,700,000円（確定920,000円・未確定780,000円）、経費108,240円を確認します。
2. 10日毎の9月上旬を選び、対象9/1〜9/10、比較8/21〜8/31、実際の経費60,240円を確認します。予算・人件費は日割りせず、月次の参考表示です。全社利益は算出しません。
3. 3ヶ月表示では、人件費が3ヶ月分の750,000円になることを確認します。前期間の実績がない場合は「実績データなし」となります。
4. 事業・担当・段階を切り替えます。担当条件には共同担当の案件とその売上・請求・入金も含み、重複加算しません。未設定月の予算・人件費は0円と区別して「未設定」となり、部分合計を全期間の予算とは表示しません。
5. 総務担当に切り替え、予算・利益・人件費・支援記録が見えないことを確認します。CSV内容・コピーと印刷プレビューも同じ範囲です。

## 2. 案件と成約

1. 経営者または総務担当で案件を開き、詳細・編集・取引先・主担当／副担当・予定を確認します。
2. 金額360,000円の案件で売上予定を100,000円にし、成約しようとすると合計の不一致が表示されます。
3. 予定を360,000円へ直して成約します。成約だけでは売上計上額は増えません。計上は別の操作です。
4. 取消や終了状態からの再開で理由を求め、関連データを残す流れを確認します。

## 3. 売上・請求・入金

1. 220,000円のイベント案件の売上予定を開き、計上金額・日付を確認して計上します。
2. 請求・入金予定を2回へ分割し、各110,000円と各予定日を指定します。合計が計上額と違う場合は登録できません。
3. 請求実績より先に入金を登録すると上限エラーになります。請求110,000円、入金110,000円の順で登録できます。
4. 実績登録後の一括／分割切替は制限されます。入金の取消では理由を付け、原実績と取消記録が残り、入金額・残額が変わることを確認します。

## 4. 経費と締め

1. 経費の未分類2件を開き、FP事業等の選択→確認→登録を試します。候補は日本デザインを自社不動産事業と日本酒の間に含む10区分です。分類修正では理由と回答者が表示されます。
2. 手入力、重複候補、要確認・連携確認待ちの説明が分かるか確認します。UPSIDER由来の金額・利用日は通常編集できません。
3. 経営者で月次締めを開き、未分類を解消して仮照合を行います。照合後に経費等を変更すると再照合が必要です。
4. 再照合後に締め、理由を付けて解除します。締め版と解除理由は履歴に残ります。
5. 上部の状態で競合・照合失敗・遅着データ等を試します。競合時は現在値と入力値を比べて再適用できます。遅着は架空の経費を追加するデモです。

## 5. 活動・次の行動

1. 総務担当で活動を登録し、複数の次の行動を追加します。
2. 指定日・期限・期間・日程未定を切り替え、担当と内容を登録します。日程未定は日付のある行動の後に並びます。
3. 完了者・日時、取消理由が残ることを確認します。活動を取り消しても関連する行動の記録を残します。

## 6. スマートフォンと一時アクセス

1. スマートフォン幅でメニューを開閉し、経営者の支援記録へ移動します。事業またはメンバーを指定し、「記録する」からコメントと追記訂正を試します。
2. システム担当へ切り替え、一時アクセスを理由付きで申請します。
3. 経営者へ切り替え、申請者と理由を確認して24時間許可、または拒否します。
4. 許可した場合はシステム担当へ戻り、期限と閲覧範囲を確認します。経営者による取消、または期限切れのデモで秘匿画面へ入れなくなります。
5. キーボードではメニュー内のTab移動とESCによる閉じる操作、開いたボタンへのフォーカス復帰を確認できます。

## 7. 取引先・管理・設定

1. 同名の取引先を登録し、候補を確認したうえで別取引先として作成できることを確認します。総務による統合では統合先と理由、旧取引先の履歴を確認します。同じ名前でも別IDの既存案件は変わりません。一覧の「編集」で名称・種別を理由付き変更でき、IDは変わらず、同じIDの案件だけに名称が反映されます。案件側から別の取引先へ変更した場合も、詳細の取引先履歴を確認します。
2. システム担当で利用者の追加・役割変更・無効化、事業・メンバーの有効期間・主所属・兼務を試します。各所属の「所属期間を変更」から開始・終了日を個別に設定できます。主所属・兼務・期間の変更前後、理由・実行者・日時を「変更履歴」で確認します。無効化でも開始日前の終了日は拒否します。最後のシステム担当は無効化できません。
3. 経営者で月次予算・人件費の金額と理由、全社プロジェクトを確認します。未設定月も開け、項目ごとに「登録」できます。0円を登録すれば「未設定」と区別され、初回登録前の値も履歴では「未設定」です。総務の採否・完了等の制限も確認します。
4. 「運用開始前」のデモで、経営者の本番開始確認を試します。年度変更・復元は申請と承認／拒否の画面までです。実環境は変更しません。

## 指摘の残し方

次の情報があれば、同じ操作を再現して修正できます。

| 項目 | 記録例 |
| --- | --- |
| 役割・画面 | 総務担当／経費 |
| 操作 | 分類済みの明細を開いて修正 |
| 気になった点・期待 | 修正理由をもう少し近くに表示したい |
| 対象版・確認者・日付 | コミット、氏名、確認日 |

まず要件責任者が操作性・見た目と画面の過不足を確認し、修正後に役員が表示項目と判断への有用性を確認します。結果は [READMEのレビュー記録](README.md#レビューの進め方) とIssue #13に記録します。
